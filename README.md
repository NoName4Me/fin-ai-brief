# AI日报

每日AI资讯简报，覆盖技术、模型、政策监管、行业场景、资本项目、风险安全和工具开源。金融与AMC是重点关注领域，所有内容统一筛选、归组和编排。

## 本地运行

需要Node.js 24和独立PostgreSQL数据库。Web与Worker调用同一份业务模块，任务使用pg-boss；模型通过环境中配置的兼容接口调用。

```bash
mise install
npm ci
cp .env.example .env # 已有 .env 时不要覆盖
npm run db:migrate
npm run dev
```

`dev`同时启动网页与Worker；也可分别使用`npm run dev:web`、`npm run dev:worker`。默认网页端口3100。数据库迁移前停止Worker，完成后重启。模型、邮件和采集遵循各自开关，浏览页面不触发模型请求。

必要配置：

- `DATABASE_URL`：独立数据库，账号需要建表和创建pg-boss schema的权限。
- `ADMIN_PASSWORD`：至少12位；`APP_SECRET`：至少32位，用于退订签名，部署后保持稳定。
- `SITE_URL`：收件人可访问的站点地址，本地为`http://localhost:3100`。
- `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`：兼容接口根地址、密钥和实际模型标识；根地址不含`/chat/completions`。
- `MODEL_CALLS_ENABLED=true`允许模型请求；自动采集在管理台开启。每日调用额度在出刊设置维护，失败请求也占次数，成功缓存不重复计次。

本机管理员密码保存在忽略提交的`.data/local-admin.txt`，运行连接和密钥留在本地`.env`。

## 内容与出刊

- 每天出刊，含周末和节假日。北京时间前一日08:00（含）至当日08:00（不含）为普通资讯窗口，生成完成后发布和投递。
- 六个全局栏目各有条数目标、条数上限和整体字数预算，接受短刊与栏目空缺。今日要览最多5条，每条30字，只引用当期评分达到4.3的事件。
- 五个维度分别按1—5分评分：相关性30%、影响面20%、时效性20%、可行动性20%、信息增量10%。3.5分进入日报候选，页面和邮件展示最近半星；管理台能查看原始分数和理由。
- 可行动性指材料提供的具体可用参考，不假设公司资源与需求，不强制写行动建议。
- 周一一周观察、隔周周三他山之石、周五数据一图／观点摘编按材料安排。隔周以管理台基准日期所在周为第一周；素材不足跳过。回顾采用对应7/14天周期，普通日报仍保持24小时窗口。
- 默认自动发布；关闭后保存待审稿。正式发布同时控制网页公开和邮件投递。重新生成待审稿时原正式版保持可读，修订不自动重发。
- 独立周报、月报暂停生成与自动推送，读者入口隐藏；7×24资讯页暂时隐藏，后台采集处理继续。

每期栏目和轮动结果在「任务管理 → 出刊任务 → 详情」查询：未排期、正常跳过、处理异常、待发布、已刊登，附候选数、采用数、理由和时间。全部材料缺失且来源或处理异常时不发布空刊。

## 重新处理与重新出刊

任务管理提供按时间范围重新处理，可选择旧规则或失败资讯、范围内全部资讯。创建批次只登记任务和原始状态快照，Worker随后按现有额度、并发与重试设置执行，页面可查逐条结果；关闭浏览器不影响执行。单批最多500条、范围最多31天，重叠未完成批次会被拒绝。

重新生成某期日报时，提供「先重新处理资讯」选项，默认不勾选；勾选后由系统先处理该期完整窗口，再更新日报。原正式版保持可读到更新成功，重处理更新遵循发布审核开关且不发送邮件。

每次出刊的栏目、候选、准确分数、维度理由与采用结果保存到对应任务的详情，不被同一期后续重出覆盖。超过字数预算时，系统只压缩超限栏目并复核；失败会保留原正式版，可从任务管理重试。

## 信源

优先采用经实际验证的RSS，保留不可替代的一手监管来源和已适配官网例外。机器之心官方RSS至少60分钟一次，令牌保存在服务端`JIQIZHIXIN_RSS_TOKEN`，不写入订阅地址或公开页面。

```bash
npx tsx --env-file-if-exists=.env scripts/audit-ai-sources.ts
npx tsx --env-file-if-exists=.env scripts/setup-ai-daily.ts
```

核查脚本只读RSS，不调用模型或导入资讯。配置脚本只为本轮成功验证的Hugging Face Blog、OpenAI、Google DeepMind添加官方RSS；新增项启用，已存在项的启停状态保持原样。其他候选不批量启用。原始抽样结果在`.data/source-check/ai-daily-rss.json`，结论在[核查文档](docs/ai-daily-sources.md)。

采集保留简短摘要和原文链接，不镜像全文。无明确发布时间的RSS不以采集时间冒充发布时间；日期精度单独保存。支持ETag、304和Retry-After，同站限流与失败退避共用。部署网络的可达性仍应实际检查。

## 邮件

QQ邮箱使用`smtp.qq.com`、465端口、`SMTP_SECURE=true`；`SMTP_USER`填完整邮箱，`SMTP_PASSWORD`填授权码，`MAIL_FROM`使用获准的发件地址，例如`AI日报 <你的邮箱@qq.com>`。

开启真实邮件前配置`SMTP_*`、`MAIL_FROM`、`SITE_URL`，再设置`MAIL_ENABLED=true`并重启。`npm run mail:verify`只验证连接与认证，不发邮件。普通日报首次正式发布创建投递；旧刊不会因后来开启邮件而自动补发。投递结果不确定时停止自动重发；手动推送可选择已发布刊期。

补刊始终保存待审稿，审核后也不自动投递；需要时在订阅管理手动发送。半星邮件同时提供数值文本，具体字形和裁切效果取决于客户端。

## 验证

测试数据库连接放在忽略提交的`.data/test.env`，库名必须以`_test`结尾。

```bash
npm run typecheck
npm test
npm run build
npm run test:browser
```

浏览器测试自动启动3101端口的独立测试Web，关闭模型和邮件，不运行Worker；不使用当前工作数据库。浏览器与业务测试不并行运行，避免相互改动测试资料。测试覆盖新日报及历史快照兼容、跨旧行业归组、评分和半星、篇幅、轮动记录、时段、审核与投递幂等。
