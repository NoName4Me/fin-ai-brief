# Fin&AI简报

金融与AI资讯简报系统。独立实现，只有网页与邮件两个内容出口，管理端直接维护信源、行业栏目和出刊规则。

技术栈：TypeScript、Next.js / React、PostgreSQL、Drizzle、pg-boss。通过 HTTP 调用 OpenAI 兼容模型接口，地址、密钥和模型名在 `.env` 配置，无模型编排框架。

## 本地运行

需要 Node.js 24 和 PostgreSQL。请使用独立的项目数据库，连接信息保存在本地 `.env` 中。

```bash
mise install
npm ci
cp .env.example .env # 已有 .env 时不要覆盖
```

在 `.env` 设置：

- `DATABASE_URL`：独立数据库，数据库账号需要建表和创建 pg-boss schema 的权限。
- `ADMIN_PASSWORD`：至少12位的管理员密码。
- `APP_SECRET`：至少32位随机字符串，供退订链接签名，部署后保持稳定。
- `SITE_URL`：本地为 `http://localhost:3100`。

本机独立数据库为 `fin_ai_brief`，已完成初始化；管理员密码保存于忽略提交的 `.data/local-admin.txt`，也可自行修改 `.env` 的 `ADMIN_PASSWORD` 并重启。

```bash
npm run db:migrate
npm run dev
```

`dev` 同时启动网页和 Worker，终端 Ctrl+C 关闭两者。网页与表单后端由 Next.js 在同一端口提供，不再单独运行 HTTP API 服务。也可以分别运行 `npm run dev:web` 和 `npm run dev:worker`。修改环境变量后重启。开发模式自动将本机局域网IPv4加入Next.js开发访问白名单，支持通过IP访问热更新和交互组件；本机IP变更后重启开发服务。

模型配置示例（Magpie）：

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=填写 DeepSeek 的 Key
LLM_MODEL=deepseek-flash
MODEL_CALLS_ENABLED=true
```

`LLM_BASE_URL` 填 API 根地址，不包含 `/chat/completions`。模型名使用服务商实际提供的标识；切换服务商时同时替换 Key。本站次数额度与服务商账户余额分别管理。

## 验证业务流程

1. 先按 [信源对比](docs/sources.md) 选定国内来源，再在管理端添加或启用。信源按行业分组；候选不会自动导入或启用，也可手工导入摘要。
2. 确认来源后配置 `LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`，在出刊设置开启自动采集，并开启 `MODEL_CALLS_ENABLED`；当前本机已恢复指定四家AI来源的采集与处理，金融已接入央行、金融监管总局、证监会、上证报金融频道及中国银行保险报。
3. Worker 采集、去重，将资讯交给模型筛选与归组。原始摘要和链接保留，不抓取外部新闻全文。
4. 工作台选择出刊日期与类型，预览事件数、缓存状态和潜在费用后确认生成。固定版式，无编辑器。默认生成成功后直接发布；管理端可切换为人工审核。
5. 已发布简报重新生成时，原正式内容保持可读，直到新稿发布。公开页面不读取草稿、不触发模型调用。

日报覆盖出刊前24小时，周报可选周几（默认周一）并覆盖此前7天，月报可选1至31号（默认1号），超过当月天数时在月末出刊。月报覆盖上个月计划出刊时刻至本次计划时刻，避免31号跨大小月漏算或重叠；边界均为各类型所设出刊时刻，统一北京时间。出刊设置可分别维护日周月时刻和起刊日期；旧设置承接原有统一时刻。日报、周报、月报定时开关默认开启。Worker 每分钟检查当期，不自动补齐长期历史缺期；次数用完后等待恢复；模型失败按60秒起指数退避自动重试，最多3次。手动补刊先预览缺期数，再确认安排，单次最多100期。

通用JSON信源响应为数组，最多100条，每条形如：

```json
[
  {
    "title": "资讯标题",
    "url": "https://example.com/news/1",
    "excerpt": "来源摘要",
    "publishedAt": "2026-10-22T07:30:00+08:00"
  }
]
```

RSS只接收含明确时区与发布时间的条目；没有时间的内容不会用采集时间冒充发布时间。默认每30分钟检查，支持ETag和304，遇429遵守Retry-After。只导入最近7天；订阅缺少摘要时读取原页简介，不存全文。AIHOT选择JSON格式，解析其最新50条精选资讯API，保留原始来源、分类及内部汇集记录；读者只看原始来源，不导入其成品简报，也不请求其境外原页来补充简介。

本机代理使用198.18/15 Fake-IP DNS时，可设置 `SOURCE_FAKE_IP_ENABLED=true`；正常DNS环境保持false。该设置只允许域名解析到Fake-IP，内网、回环与直接填写的Fake-IP地址仍拒绝。

管理端「出刊设置 → 模型调用额度」只限制每日调用次数，默认100次，按北京时间零点计数。失败请求也占用次数，成功缓存复用不新增次数。用完后等待次日或调高上限，Worker自动续排。模型任务失败自动重试最多3次，不要求人工核对或放行。输入、结果和token可在资讯处理详情内查看，不再提供独立模型与额度页、价格或金额预算。

新智元使用官方文章列表HTML，已适配标题、简介、原文和日期精度；机器之心已配置官方免费RSS，令牌保存在服务端 `JIQIZHIXIN_RSS_TOKEN`，至少60分钟一次；首次空摘要解析已修复，限频后继续验证入库。已指定AI名单与金融接口实测见 [信源核查](docs/sources.md)。

简报正文与左侧列表共用AI生成的本期主题，字数上限在出刊设置配置，默认36字（含标点，可设1至200字），超出拒绝写入，已发布内容不受后续缩短上限影响。7×24资讯独立阅读，无简报归档侧栏；实时开关控制SSE连接，新内容先提示数量，不自动插入或改变阅读位置。点击提示后合并内容、返回列表顶部并标出新条目；断线或重新开启按游标补齐，关闭后可手动刷新。分页和推送均只读，不触发模型请求。

金融五家已接入并启用，默认每30分钟检查。央行与证监会保留日期精度，监管总局读取监管动态、政策法规、政策解读和征求意见；上证报限定金融频道，详情使用其公开移动端内容API；银行保险报仅读取已选定金融栏目。已收录原文不重复读取详情。首次配置可运行 `npm run sources:finance`，脚本保留现有启停与间隔设置。

## 邮件状态

邮件模板已同步阅读页的刊期日期、期号、行业总览、头条与分栏、摘要重点及来源链接，日报／周报／月报分别排版。采用内联样式与表格布局，手机端折为单栏；邮件客户端的字体与CSS支持可能造成细节差异。已发出的邮件不会随模板更新改变。

订阅登记、退订、名单管理、邮件模板、发布投递记录与 SMTP 接口已实现。管理台菜单已提供「订阅管理」：可新增订阅、多选有效邮箱，选择已发布的日报／周报／月报（含历史刊期）后手动推送。手动推送不修改原有订阅类型；默认勾选「强制推送」，已发送或结果待确认的投递也可手动重新入队；关闭后跳过这两类记录，明确失败的投递仍可重试。排队中、发送中的记录始终跳过，并发重复提交不会重复排队。每次实际发送使用新的Message-ID，避免补发邮件被当作同一封邮件。自动发布仍不重试已有投递。近期发送结果显示收件邮箱、刊期和状态。

当前使用QQ邮箱发信：`SMTP_HOST=smtp.qq.com`、`SMTP_PORT=465`、`SMTP_SECURE=true`。在QQ邮箱网页端开启SMTP服务并生成授权码；`SMTP_USER` 填完整QQ邮箱地址，`SMTP_PASSWORD` 填授权码，`MAIL_FROM` 填同一邮箱地址（可带显示名，例如 `Fin&AI简报 <你的邮箱@qq.com>`）。配置未完成时保持 `MAIL_ENABLED=false`。授权码说明：https://help.mail.qq.com/detail/106/985 。

Coremail和Gmail的接入暂不使用。切换服务商时同步替换SMTP账号、授权码和发件地址。

确认连接信息后配置 `SMTP_*`、`MAIL_FROM` 和收件人可访问的 `SITE_URL`，完成测试后开启 `MAIL_ENABLED=true`，重启 Web 与 Worker。`SMTP_HOST` 只填域名，不含 `https://`；465 + SSL 对应 `SMTP_SECURE=true`，587 + STARTTLS 对应 `SMTP_SECURE=false`；以单位实际设置为准。`SMTP_USER` 通常为完整邮箱地址，`SMTP_PASSWORD` 按单位策略使用客户端专用密码或邮箱密码，`MAIL_FROM` 使用该账号获准发送的地址。开启前的历史简报不会自动补发。已退订者不创建新投递；发出前再次检查订阅状态。普通简报首次正式发布时创建投递；重新生成或发布修订只更新内容，即使旧投递记录已清理也不自动重发。补刊始终先生成待审稿，审核发布后也不自动推送；需要发送时在订阅管理选择刊期和邮箱。手动强制推送可重发同一期。

可运行 `npm run mail:verify` 单独验证当前SMTP连接、加密与认证，不会发送邮件。连通与认证通过也不代表目标收件箱已收到邮件。

连接、认证失败或SMTP明确拒收时标记“发送失败”，保留脱敏后的错误码与原因；提交结果无法确定时标记“结果待确认”。邮件均不自动重发，避免对方已经收信却再次投递。Worker被强制终止时处于“发送中”的记录，也需要核对服务商记录。当前没有接入退信、投诉回调或邮箱验证；正式开放外部订阅前随服务商一起补齐验证流程。

## 处理与运维入口

普通资讯通过材料校验、同业候选召回后，通常用一次综合调用完成相关性、评分、事实与原文证据提取、标题摘要、归组和新增事实判断。归组疑难或事实冲突时按设置额外复核一次。复核不同意时保留独立事件，以原摘要、0分和复核说明等待人工检查，不混入正常选题。重复转载只挂接来源，不反复重写综述。事件进展按日期落库，周月报直接综合对应周期的事实资料。

任务管理位于`/admin/articles`：采集、资讯、出刊统一为一个任务列表，依次展示任务类型、任务名、开始时间、状态、操作。支持按类型、状态筛选及任务名搜索；手工导入位于筛选上方，刷新保留当前筛选。详情按需加载原始材料、步骤、起止时间、结果及关联回执，旧`/admin/jobs`入口跳转至统一页。综合步骤明确标注共用一次调用。重试复用成功阶段；修改输入、规则或模型会改变处理版本键。历史资料没有记录的时间和关联不推算补写。采集失败显示当时信源名称、ID、地址、时间和错误。

每源支持固定或自动间隔、最短和最长界限、当前间隔及调整原因。自动模式按该源列表新增量调频，不受跨源去重和精选结果影响；连续无新增逐步放慢，稳定有新增逐步加快；失败退避，成功后观察恢复，不立即提频。429遵守Retry-After，同域名请求含详情至少间隔1.5秒，共享限流暂停。固定模式不按产量调频，但失败仍暂时退避。机器之心不突破60分钟下限。升级保留现有间隔，各来源自动模式默认关闭，按需开启。

### 升级到处理可追溯与SSE版本

先停止Worker，运行`npm run db:migrate`应用0008迁移，再启动Web/Worker。新增调用关联、处理步骤、采集记录、事件进展、实时变更和同站调度状态，不删除已有资料。原环境采集开关已移除：在管理台保存自动采集启停；已有部署升级时应按原启停状态保存一次。模型和邮件运行开关仍在环境变量。

本次本机已将原采集启停状态、日周月原统一时刻写入数据库，起刊日期承接最早已有刊期，没有批量补刊、重算历史资讯或发送邮件。未开始的新处理才使用新链路。现阶段统一使用环境中的LLM_MODEL、API与Key；管理台不再提供分任务模型设置，事实复核仍使用同一个模型。

### 简化模型次数限制

升级0009迁移会移除金额预算设置及model_calls中的estimated_cost、currency列，保留调用次数、输入输出、token和处理阶段；旧未知状态自动转为失败，移除人工放行。模型请求失败可自动重发；进程中断遗留的发送状态超过5分钟自动释放。同一时刻的有效请求仍防重复，成功结果仍缓存。所有重新发送计入每日次数。模型请求使用低推理强度，保留12000 token输出空间，避免推理耗尽上限导致空正文。

金融简报每条目标70至120字，上限140字；金融概览上限120字。AI篇幅保持原规则。资讯处理详情用竖向时间线展示阶段。


### 任务重试、并发与优先出刊

在「出刊设置 → 任务处理」配置失败后的自动重试次数（默认1次、范围0—3次，不含首次执行）和资讯并发数（默认3篇、范围1—20篇）。重试上限写入新入队任务，已有任务沿用入队时的上限；并发设置保存后由Worker自动应用，调整时先完成正在执行的任务。采集、资讯处理、简报生成可重试，邮件维持不自动重发。模型失败请求计入每日额度；额度等待不消耗重试次数。

资讯重试耗尽后标记失败，保留步骤、回执和手动重试入口，不再阻塞对应时段出刊。Worker会识别过期、中断或升级前遗留的队列终态失败并同步资讯状态。手动重试创建新任务并复用成功阶段。

重新生成日、周、月报时，若本期有未完成资讯，先展示强制生成确认。确认后持久保存生成请求，并优先调度本期资讯，全部处理成功或达到重试上限后再优先生成；等待资讯不会占用生成Worker或消耗生成重试。已经开始执行的其他任务会正常结束；达到每日额度时等待额度恢复，不绕过预算。请求进度在「任务管理」统一列表查看。正常生成继续校验预览版本；强制生成使用依赖完成后的最新资料。

并发保存时串行提交事件变化，相同标题或相同事实的跨来源结果在保存时再次查重；同一事件被并发更新时重新召回和分析，避免旧摘要覆盖新进展。相同输入的同时请求共用模型回执。

升级时运行`npm run db:migrate`应用0009迁移，再启动Web和Worker。此迁移新增失败状态和持久生成请求，不删除已有资料。操作反馈改为右上角通知，成功提示5秒后关闭，失败提示保留至手动关闭；资讯及任务时间线最新在前。

管理台左上角显示“Fin&AI 管理台”，右上角退出管理台；左侧菜单高亮当前位置，不展示邮箱订阅入口，各业务页移除重复的大块标题栏。公众阅读页保留原有导航和邮箱订阅。自动重试保留同一任务行，手动重试新建任务；手动出刊请求与其生成任务合并展示，等待资讯、等待额度保留为明确状态。新入队的采集和资讯任务记录对象名称快照，来源改名或删除后仍能识别原任务。


## 分类、刊头与数据保留

网页与邮件均按行业内配置的分类顺序聚合，分类内保留本期选题顺序；不再把板块首条自动标成“重点关注”。日报、周报、月报都以本期主题为大标题。周报右侧依次显示年月、ISO周次、完整日期区间、期号；月报显示年份、月份大数字和期号。7×24按事件最新来源发布时间倒序，同一时刻按ID倒序稳定排列。

管理台「数据保留」可设置自动清理、资讯保留天数（默认30天）、任务与过程数据保留天数（默认30天）。邮件推送记录默认保留7天，可调整；与资讯和任务一样，每天按滚动保留天数检查并清理已结束记录。Worker每天北京时间03:20执行，也可在管理页按已保存规则立即清理。

日报、周报、月报草稿与正式快照、来源链接、信源配置、行业和订阅名单始终保留；过期资讯、原始材料与相关事件进展可删除。模型调用、处理步骤、采集日志、出刊请求与终态任务按过程数据保留天数清理，正在执行或等待中的任务保留。原始材料删除后，历史简报仍可阅读与推送，重新生成不能使用已删除材料。

为避免未出刊月报缺少材料，月报统计范围内尚需使用的资讯暂缓物理删除；7×24展示仍按配置天数截止。邮件终态记录清理后不再阻止手动推送同一期；简报修订仍不自动重发。待发送、发送中的记录不会中途删除。


## 正式刊期切换与统一样式

简报中心仅显示已发布数据，不再自动回退至周报/月报版式示例，旧sample参数不改变内容。无正式月报时显示空状态；示例中的9月月报不属于正式归档，不创建期号或补入列表。月报按统计月份所属年份分组，跨年刊期归入统计区间年份。

侧栏日报/月报日期数字使用25px粗体，周报显示ISO周次及左上起始日、右下结束日。周报/月报沿用日报的墨蓝色、概览底色、板块标题和打印入口位置；移除重复日期行、额外的“本周要情/主题复盘”总标题，资讯日期贴近标题。正文各期原有布局保持，网页与邮件同步。
