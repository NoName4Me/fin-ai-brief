## 运行故障的最短路径

1. 在管理台确认相关总开关、连接配置和任务状态。
2. 查看 [邮件推送的状态机与排查顺序](mail-delivery.md#状态机) 或 [模型运行的三层重试](model-runtime.md#三层重试的区别)。
3. 检查 Worker 心跳、容器状态与日志，具体命令见 [部署运维](deployment.md#5-生产配置和排查)。
4. 涉及数据恢复时先阅读 [备份、恢复与回退](deployment.md#4-备份恢复与回退)，不要在应用仍运行时直接改表或覆盖数据卷。

## 文档约定

- “推送”和“投递”都指把已发布日报交给 SMTP；产品页面使用“推送”，内部状态与表结构使用 `delivery` 或“投递”。
- “发送”指一次 SMTP 提交尝试；“送达”表示收件服务器已接受邮件，不保证进入收件箱。
- “自动投递”由首次发布触发，“手动推送”由管理员选择刊期和订阅者触发，“单条重推”只面向 `failed` 投递。
- 状态名、阈值和命令以正文及其标注的实现入口为准。上线前已执行的 SQL 迁移不修改，结构变化新增迁移文件。

## 维护方式

新增或调整文档时直接编辑 Markdown，然后执行：

```bash
npm run docs:build
```

生成的静态页包含文档 Tab、当前页目录、跨文档搜索、信源筛选、代码复制和 Mermaid 流程图。页面完全从本地文件生成，不依赖在线字体、图表服务或外部脚本。静态页仅供本地阅读，不进入部署包，也不由 Nginx 对外发布。
