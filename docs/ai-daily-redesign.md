# AI日报改造方案

确认日期：2026-10-26。本文记录本次讨论确认的目标，供实施和验收使用。原有 README、architecture.md 中的实现描述以实际代码为准，随改造更新。2026-10-26 用户已授权：文档落地后直接实施，无须再次等待确认。

## 定位与范围

- 最终名称为「AI日报」，沿用现有简报的视觉风格。
- 日常参阅为主，帮助读者快速了解重要变化；具体应用、选型和建设参考为辅，只在材料支持时提供。
- 只关注 AI。金融、AMC 是重点关注的领域，涵盖政策监管、风险治理、资本、采购、机构与应用等多个方面，不只是应用场景。
- 收录直接讨论 AI 的内容，以及能明确说明会改变 AI 研发、部署、采购、使用条件的内容。普通金融新闻、泛数字化动态和无法说明 AI 关联的政策不纳入。
- 暂不建设「内部动态」「建议动作」模块，不要求每条资讯附行动建议。

## 统一内容组织

- 统一资讯池，取消 AI 与金融互斥的行业分区及其对采集、处理、归组和成稿的限制。
- 每个事件只有一个主栏目，可以有多个标签。金融、AMC、银行、智能体、数据安全、采购等可作为标签。
- 信源可配置多个候选栏目；未选为通用。资讯只在信源允许的栏目中按内容判断，仍需通过AI关联与质量筛选。同一事件跨源去重后只刊一次。
- 栏目负责日报结构，标签描述属性，关键词负责召回，轮动栏目负责综合与解读。管理台应分别管理这些规则。
- 「技术与模型」侧重模型能力、技术与协议进展；「工具与开源」侧重可取得的软件、工具和开源项目。政策文件主归「政策与监管」，具体漏洞、事故和风险事件主归「风险与安全」。跨栏目事件只刊登一次。

## 每期结构与篇幅

| 内容       | 正常条数目标 | 总字数预算        | 优先级 |
| ---------- | ------------ | ----------------- | ------ |
| 今日要览   | 3—5          | 150，每条最多30字 | P0     |
| 政策与监管 | 1—3          | 250               | P0     |
| 技术与模型 | 2—4          | 350               | P0     |
| 同业与场景 | 2—4          | 400               | P0     |
| 资本与项目 | 1—3          | 250               | P1     |
| 风险与安全 | 1—2          | 150               | P1     |
| 工具与开源 | 1—3          | 200               | P1     |

- 字数为该栏目整体预算，条数为正常目标。接受短刊和空缺，不补低质量内容，不为达到下限凑稿；要览不足三条时同样可以少发。
- 无合格内容的栏目不在读者页面展示，但管理台应可查原因。
- 要览浓缩当期入选资讯，不增加独立事件；合并原来重复的领导速览内容。
- 每条保留标题、事实摘要、来源、评分星级。必要时提供有事实支持的背景、应用参考或限制条件，不泛写「值得关注」。
- 区分事实、厂商/机构自述、计划、传闻和编辑分析；引用多个转载源不等于独立验证。

## 轮动栏目

| 栏目               | 排期     | 内容与预算                                     |
| ------------------ | -------- | ---------------------------------------------- |
| 一周观察           | 周一     | 过去一周3—5件事及有材料支持的趋势判断，约500字 |
| 他山之石           | 隔周周三 | 拆解一家同业或厂商的做法，约400字              |
| 数据一图／观点摘编 | 周五     | 一图一趋势或有出处的观点摘编，约300字          |

- 轮动内容放在日报内，不恢复独立周报/月报；素材不足可跳过，不强行编造图表或趋势。
- 回顾与案例采用其对应的取材周期，不受普通日报24小时窗口限制。
- 管理台按刊期、栏目保留：未排期、正常跳过、处理异常、已刊登。记录候选量、采用量、跳过/淘汰理由与执行时间。
- 采集或处理失败不能记成「没有内容」。普通栏目同样需要可追溯的空缺记录。
- 轮动栏目计入整期篇幅安排，避免无限叠加。隔周排期基准、图表形式等实施细节单列说明，不伪装成已确认要求。

## 召回、证据与评分

流程：关键词召回 → AI关联与证据检查 → 统一事件归组和去重 → 五分制评分 → 按栏目与篇幅选题 → 成稿。

- 关键词组覆盖政策、技术模型、智能体工程、金融同业、资本项目、招投标与风险安全。
- 「数据泄露」「知识库采购」「AMC数字化」等宽泛词只用于找线索，必须继续确认 AI 关联；不限制重要非金融 AI 资讯。
- 入选前检查来源可追溯、事实有材料支持。重要性高不能补偿证据不足。
- URL去重之外按事件归组，同一事件原则上一条，有实质新增事实才再次报道。

| 评分维度                         | 权重 |
| -------------------------------- | ---- |
| 相关性                           | 30%  |
| 影响面                           | 20%  |
| 时效性                           | 20%  |
| 可行动性（具体、可用的参考价值） | 20%  |
| 信息增量                         | 10%  |

- 每个维度1—5分，加权分≥3.5进入日报候选，≥4.3进入要览候选。再根据去重、条数与篇幅选择，不保证达到阈值就全部刊登。
- 相关性面向 AI 及目标读者，不要求每条对应公司现有场景。
- 可行动性：1分=用于了解动态，缺少明确工作参考；3分=有具体相关场景，但条件、效果或使用方式不充分；5分=有明确可参照的要求、方法、工具或案例，关键条件有材料支持。2、4分为中间档。
- 可行动性理由必须指向材料，不猜测公司资源与需求，不因写出一句建议就加分。
- 后台保留准确加权分和各维度理由；展示按最近的半星舍入，支持0.5星。入选使用准确分，不使用展示舍入值。

## 信源核查

- 合并三份参考材料与项目已有信源，优先核查并复用已经验证的入口。
- RSS优先，实际检查是否可用、更新、摘要和时间字段是否足够；清单标注RSS不代表已经验证。
- 原始发布源和有独特采访、解读的专业来源优先。按低质量内容、转载重复和独特信息贡献评估来源，形成保留、补充、淘汰、待验证名单。
- 没有RSS但不可替代的官方来源可以保留例外；有RSS但噪声高的来源也可以降级。
- 不把公众号采集作为默认主通道；按实际入口能力选择已有RSS、公开接口或已适配网页。
- 区分信源监控优先级与内容刊登优先级。P0应理解为优先监控，不是每天必须刊登。
- 参考材料中的技术状态和政策结论只作为待验证线索，不照搬为产品规则或已核实事实。

## 出刊与发布

- 每天出一期，含周末和节假日，统一Asia/Shanghai。
- 普通日报窗口为前一日08:00（含）至当日08:00（不含）。08:00是截稿点，生成完成后发布和发送，不承诺08:00整完成投递。
- 默认自动发布，预留并保留管理台人工审核开关。人工模式生成待审稿，统一在正式发布环节控制网页公开与邮件投递。
- 独立周报、月报暂停定时生成和自动推送，隐藏读者入口；7×24资讯页暂时隐藏，后台采集处理继续。
- 保留历史正式内容，不因新定位自动删除、改写旧刊或自动重发邮件。
- 原样刊的工作日、周末停刊、前晚20:00截稿、08:00/08:30发刊等安排，被本节最新确认覆盖。

## 实施顺序与验收

1. 统一分类与管理配置：取消互斥行业约束，建立全局栏目、标签、关键词和评分规则。
2. 核查信源并调整采集筛选：RSS优先、去重和质量筛选，统一AI关联判断。
3. 改造处理与生成：全局事件归组，五维评分与理由，栏目篇幅预算、要览、轮动内容与空缺原因。
4. 改造出刊与发布：每日08:00窗口、自动发布/待审控制、停止周月定时与自动推送。
5. 同步网页、邮件和管理台：更名AI日报，保留现有视觉风格，半星展示，隐藏周月报与7×24入口。
6. 验证数据迁移与历史阅读、跨旧行业的同事件归组、评分门槛和半星、栏目预算、短刊与异常状态、时间窗口、审核阻断网页和邮件、任务与投递幂等。

实施时补充明确的迁移策略、来源实测结果和剩余边界；不将核查前的候选源直接全量启用。运行和真实发送需遵守已存在的开关与配置，不以功能开发为由主动群发。

## 2026-10-27 补充确认与实施

- 出刊记录并入任务管理。每个出刊任务的详情按栏目查看候选、五维评分、采用或跳过理由；保存任务级快照，避免同一期重出后覆盖旧任务详情。
- 重新生成某刊时可选「先重新处理资讯」，默认不勾选。勾选后系统先安排本期完整窗口内的处理任务，再生成日报。
- 任务管理也支持按时间范围发起持久批次，由Worker执行，复用并发、重试、额度与任务记录。创建批次本身不调用模型，不直接重置进行中的工作。
- 重处理后的日报遵循自动发布/人工审核设置，保留原正式版到更新成功，不发送邮件。
- 当前用户手动管理3100服务，助手不再自行启动或恢复该服务。

- 栏目字数超限时由系统定向压缩并重新校验，不放宽预算或直接截断。失败出刊可从任务管理重试，原任务详情快照保留。
- 本轮通过管理台创建了2026-10-25 08:00至2026-10-27 00:15的108条重处理批次，并通过重新出刊选项对26日日报完整窗口再次校准评分；所有执行均由Worker及现有队列完成。本次更新未创建邮件投递。


## 2026-10-27 信源管理补充确认与实施

- 信源按七列平铺：名称、归属栏目、采集方式、验证状态、最近采集、启用、操作。质量、重复率、验证结论与采集节奏放详情。
- 栏目多选，空选为通用。处理模型只能使用该信源允许的栏目；出刊候选再次检查范围，修改配置不改写已经发布的快照。
- 表格上方支持启用状态、归属栏目和采集方式组合筛选，栏目含“通用”选项；刷新及往返详情保留筛选条件。
- 启用使用独立开关。新增默认关闭，验证不导入资讯、不调用模型、不自动启用。标为“已选用”需有评估结论和可用入口。
- 更换入口会关闭信源并撤销旧验证，避免沿用旧入口的结论。
- Excel保留81行原始清单到 `src/data/source-catalog.json`。排除中投公司、中国东方资产管理两条内部动态来源和“各银行/AMC官网采购公告”集合项；采购类具体来源仍保留。其余78条中10条合并已有来源、68条新增，共80个来源，既有12个启用状态保留。
- 来源地址/账号与实际采集入口分开。缺少入口、公众号和付费渠道仍可入库，不伪造RSS或用首页冒充订阅。
- `npm run sources:import` 幂等导入；`npm run sources:verify` 逐项检查待验证候选并记录结果，优先发现站点公开声明的RSS。失败保留原因，不能凭一次失败认定信源质量差。
- 解析成功仅标记“采集可用·待评估”；超过90天未更新、或多数条目缺少有效摘要的入口标记“暂不选用”。内容评估关注AI相关性、原始事实贡献、摘要是否充分、付费限制和与已有来源的重合。

- 本轮候选核查与内容抽样后，新增选用MIT Technology Review（技术与模型、同业与场景、风险与安全），总启用13个。其余候选保持关闭，7个明确记录暂不选用理由。
