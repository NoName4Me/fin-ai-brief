# 架构与边界

Web 与 Worker 共用业务模块和 PostgreSQL。Web 处理页面及管理操作，Worker 执行采集、资讯处理、出刊和邮件投递，任务队列使用 pg-boss。

## 代码结构

| 目录                  | 职责                               |
| --------------------- | ---------------------------------- |
| `src/app`             | Next.js 页面、接口和服务端操作     |
| `src/components`      | 阅读、管理、编辑和订阅界面         |
| `src/server`          | 内容、任务、模型、数据库及邮件业务 |
| `src/worker.ts`       | Worker 入口与定时调度              |
| `database/migrations` | 按文件名排序执行的数据库迁移       |
| `scripts`             | 开发进程、迁移和连接验证           |
| `tests`               | 业务回归测试与浏览器测试           |

## 采集与事件归组

1. `collect` 读取 RSS、公开接口及已适配网页，规范化 URL，保存来源文本、时间精度和采集记录；详情与 PDF 的抽取由对应来源适配器处理。
2. `process` 进行 AI 关联筛选、指标评分、事实提取、主栏目判断和事件归组。信源的栏目范围限制可参与栏目，辅助关键词只提供线索。
3. 单篇分析仅召回同一期统计窗口内的已评分事件，按相似度取前 12 个，只发送标题和最多 500 字符的摘要，不携带跨期历史。中文连续双字、英文词和数字参与匹配，英文词及数字加权，并按文本长度归一。
4. 模型对照本期候选事件区分重复报道和实质新增事实。后续进展必须返回新增事实索引，程序校验范围、重复及空增量；文章保存完整事实，事件进展只写入新增部分。
5. 重复报道仅增加关联来源，不新增进展。疑难归组和事实冲突可触发独立复核；复核拒绝的资料以低分保留，不进入日报。

事实依据由模型选择原文段落编号，程序提取原文，拒绝未知编号及无效引用。传闻、计划和机构自述保留归属与不确定性。原文引用校验不替代语义判断。

事件写入通过事务锁串行化，精确标题和事实哈希用于并发去重；同一事件在召回后发生更新时，重新召回并归组，避免覆盖新内容。

## 栏目与评分

栏目、评分指标、候选门槛和写作要求保存在数据库 settings 中。栏目有稳定 ID，改名保留旧名映射并同步信源范围；删除前必须解除关联，避免受限信源意外变成通用来源。

默认五项评分为相关性 30%、影响面 20%、时效性 20%、可行动性 20%、信息增量 10%，每项 1—5 分。暂停指标后其余权重归一；筛选用准确分，网页和邮件显示最近半星。旧整数 score 列保留五分制乘 20 的兼容映射。

日报候选门槛默认 3.5 分，要览默认 4.3 分。可开启材料不足时有限放宽，默认关闭、最大降幅 0.3 分；不会改写评分。指标描述改变导致旧评分不兼容时，资料须重新处理，不补零分。

固定栏目控制条数与标题、摘要合计预算；轮动控制正文预算；要览控制条数和总预算。默认超额容差 10%，主标题独立字数上限不应用容差。

## 日报生成

`daily` 按配置的北京时间截稿时刻切分 24 小时窗口，`weeklyMaterials` 读取窗口内进展及对应评分快照，避免事件后续状态进入旧刊。

固定栏目和轮动栏目分别生成、校验、缓存及重试。固定栏目按评分准备各自上限加 2 个达标候选，不设独立的整刊事件上限。
待刊候选才对照此前 7 天已刊固定栏目内容，按文本相似度召回最多 24 个历史事件，并合并同事件的多期报道。首次报道正常采用，有进展时向写作阶段提供新增事实索引及已刊背景。重复事件丢弃，每个原名额只顺位补一位；补位仍重复则留空，每栏共用两个备选，不继续递补。检查只返回事实索引，不改动原始资讯和事件；成功回执可缓存复用。预览只读取缓存，不调用模型。
要览只摘要最终入选且评分达标的正文，最后生成整期标题；这两步不再重复发送全量已刊历史。轮动素材选择和写作规则不参与本次固定栏目去重补位。

轮动取材天数为间隔周数乘 7，排期基准共用起刊日期。默认周一一周观察、隔周周三他山之石、周五数据或观点摘编；材料不足跳过。一周观察回顾 3—5 个事件并给出有依据的趋势判断；他山之石只拆解一家机构的做法与条件。周五栏目必须选择数据或具名来源观点，分别显示“数据一图”或“观点摘编”。数据类允许纯文字；有至少两个同口径、同单位的可比数值时可附横向柱形图。图表点值和观点归属均引用本期事实短编号，程序核验依据并在保存时移除内部编号。网页和邮件展示实际类型名、图表和来源，旧刊正文中的内部引用标记在展示时清理。

程序校验引用、事件重复与遗漏、评分门槛、排期和字数。固定栏目超出容差时只压缩该栏，保留其余成功结果；失败不覆盖正式刊。来源或处理异常不能作为正常无内容发布空刊。

`edition_runs` 保存刊期各栏的最新状态，`processing_steps` 保存每次任务的阶段结果及候选快照，后续重出不覆盖此前任务记录。模型成功请求可复用缓存；失败请求计入每日调用次数，额度不足时进入等待。

## 发布、编辑与邮件

正式刊期使用结构化快照，网页与邮件读取同一份 published。新日报格式为 `ai-daily-v1`，保留旧格式读取能力；历史数据中的行业、标签及旧字段不因当前配置变化而重写。

首次发布、期号分配和投递记录在事务内完成。关闭自动发布则写入待审稿，原正式版在重新生成及审核期间保持可读。补刊始终待审且不自动投递，普通修订保留期号和发布时间、不重发邮件。

全文编辑先保存 draft，发布时校验篇幅与来源关联，通过版本键防止覆盖并发修改，并保存修订前后快照。逐字段 AI 重写每次调用生成新候选，由管理员采纳后保存。

用户订阅需通过有效期 24 小时的邮件确认；管理员添加可直接生效。SMTP 连接、认证及明确拒收保留失败原因；提交结果不确定时停止自动重发。手动推送与自动推送共用投递去重规则。

## 任务、配置与数据保留

Worker 默认让模型队列任务仅在波谷运行：北京时间周一至周五 09:00—12:00、14:00—18:00 等待，其余时间及周末运行；工作日法定假日也保守按此时段等待。采集、投递和连接测试不受影响，已开始的模型任务允许完成；到波谷自动恢复等待任务，不消耗重试次数。可在模型配置关闭该限制。

Worker 按已保存的并发、重试和调用额度执行任务，每分钟检查当前刊期，不自动补齐长期缺刊。重新处理批次由 Worker 调度，最多 500 条、范围最多 31 天，重叠未完成批次会被拒绝；批次更新日报不发送邮件。

每源采集间隔至少 60 分钟，支持自动调频、ETag、304、Retry-After、同站限流与失败退避。原始资料和过程记录按系统设置清理，正式刊期快照与来源链接保留。

模型地址、密钥、模型名与调用开关保存在数据库，环境中的旧模型配置仅首次迁移时导入。SMTP 连接与发件人保存在数据库，页面推送开关统一控制所有邮件，旧环境邮件配置及双开关的有效状态仅首次迁移时导入。连接测试不发送邮件、不保存临时表单，密码留空保留原值，密码不传入客户端。数据库、管理员密码与签名密钥来自环境变量；管理写操作及任务详情接口检查管理员会话。

迁移记录文件名和校验和；已应用 SQL 不修改、不删除。升级先停止 Worker，再迁移并重启。部署与验证命令见 [README](../README.md)，信源入口见 [sources.md](sources.md)。
