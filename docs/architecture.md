# 架构与边界

一个仓库、一个PostgreSQL数据库，Web处理页面和短请求，Worker处理采集、模型、生成与投递。二者调用相同业务模块，队列使用pg-boss，不增加模型编排框架。

## 内容模型

新内容采用统一AI资讯池，每个事件一个主栏目；标签配置和新标签生成已移除，历史字段兼容保留。信源配置限定候选栏目范围（未选为通用），资讯在范围内按内容归类；关键词命中仅提供线索，所有文章再经过AI实质关联与证据检查。

`industries`及相关外键暂留以兼容历史快照；新采入和处理的内容统一使用`ai`兼容键，管理台不再配置互斥行业。事件召回、同题匹配和并发去重跨旧行业进行。固定与轮动栏目统一保存在settings.sections中，支持行内编辑、增删、改名、启停、篇幅与排期；评分指标及候选门槛和辅助关键词也保存在settings中，术语见[GLOSSARY](../GLOSSARY.md)。

## 处理链路

1. `collect`读取RSS/Atom、JSON或已适配HTML，规范化URL，保留简短摘要、原始来源、时间精度和汇集路径。
2. `process`在一次综合调用中判断AI关联、启用指标评分、事实摘录、主栏目和全局事件归组。关键词命中在材料校验记录中可查。
3. `editorial`定义栏目默认预算、可配置评分指标、加权计算、半星舍入和轮动排期。指标名称、描述、权重和启停可配置，每项1—5整数分及理由按稳定ID存入assessment；总分为启用项的加权和除以启用权重总和，暂停项不按零分计入；旧score整数列保留0—100兼容映射（五分制乘20），不直接作为星级。
4. `event_developments`保存新增事实、报道时间及当时标题、栏目、分数、assessment和标签。重复报道只附加来源，不制造新的进展。
5. `daily`按当期进展快照取材，拒绝把事件当前未来状态带入旧窗口。按原始五分制分数、栏目上限和整期上限选择，生成标题、摘要、要览与可选轮动，并校验引用、重复、遗漏和字数预算。
6. `persistBrief`保存草稿或正式快照，`publication`统一对外读取已发布内容，网页和邮件采用同一份结构化快照。

### 公众号采集

`src/modules/wechat`是独立微信协议模块，负责微信请求、公众号搜索、文章列表和正文解析，不依赖Next.js。`src/server/wechat.ts`与`src/server/wechat-auth.ts`负责扫码流程、凭证、账号和现有信源管线的适配；登录凭证使用APP_SECRET进行AES-256-GCM加密，不进入页面或日志。

`/admin/wechat`负责扫码连接，公众号在统一信源表单中添加和编辑。每个账号对应一个`format=wechat`信源，复用Worker、pg-boss、采集记录和文章去重，由该信源的采集间隔和自动调频设置触发读取。仅对新增文章读取正文，再进入统一处理管线。全局自动采集开关同时控制公众号与其他信源。

相关资讯必须包含可在来源摘要逐字找到的事实依据。机构自述、计划和传闻保留归属；疑难归组或事实冲突可独立模型复核，复核拒绝的事件保留低分资料，不进入日报。引用格式和摘录校验不等于完整的语义核实。

旧百分制资讯不自动冒充新指标评分；旧正式刊期不重写。旧资料缺少新评分而阻碍新日报时，执行记录明确报异常，不当作正常无内容。历史生成和旧版式保留为兼容能力，普通管理操作与队列停止安排周月报。

调整权重或暂停指标时，候选按当前有效权重重算，不再用旧score拦截；日报候选和要览门槛分别配置，使用准确分筛选。新增或更改启用指标描述导致旧资料缺少兼容评分时，标为待重处理，不补零分。处理与出刊任务保留当次指标名称和规则快照，正式刊期不追溯改写。

今日要览在栏目表格首行编辑，排序和类型固定；名称、条数区间、总预算、要求及启停可配置，也可删除后恢复。不设置单条字数预算，名称写入新刊快照并用于网页与邮件。

评分页可开启内容不足时放宽门槛，默认关闭、最大降幅默认0.3分。日报目标为启用固定栏目条数下限之和（不超过整期上限），计算时先按各栏上限限制候选；不足时在最大降幅内选择达到目标所需的最高可用门槛。要览按自身条数下限单独计算，门槛不低于本次日报候选门槛。评分和事实审核规则保持不变，材料不足时不强行凑满。

栏目页配置字数超额容差，默认10%。固定栏目按全部标题与摘要合计、要览按全部文本合计、轮动按正文计算；标点和空白计入字数，来源与评级不计。预算以内为写作目标，容差以内直接接受；超过容差的固定栏目交给模型压缩并再次校验，不截断正文或减少已选事件。要览、轮动超限走生成校验重试；校验仍失败时不覆盖正式刊。主标题独立上限不应用容差。

栏目用稳定ID维护身份，改名保留旧名映射并在事务中同步信源范围；历史进展仍可归入当前名称。删除或改为轮动前必须解除信源关联，防止受限信源因列表清空意外变成通用。暂停栏目不参与新处理和出刊。

## 出刊与记录

普通日报每天08:00北京时间截稿，覆盖前一日08:00（含）至当日08:00（不含），含周末和节假日。起刊日期、采集启停与每日出刊启停仍由管理台控制。08:00为统计截止，生成完成后发布。

`edition_runs`按刊期和栏目保存最新执行结果及候选数、采用数、理由和时间，支持未排期、正常跳过、处理异常、待发布、已刊登。每次generate任务在processing_steps的edition阶段另存当次栏目结果及候选明细快照，任务详情读该快照，后续重出不会覆盖先前任务的结果。来源失败、未成功采集、区间资料处理失败或旧评分缺失会影响空缺判断，不能静默转成正常跳过。

默认周一一周观察使用七天资料，隔周周三他山之石使用十四天，周五观点/数据摘编使用七天。每个轮动栏目独立配置星期、间隔周数、引用事件数与字数；取材天数自动为间隔周数乘7，排期基准共用系统起刊日期；生成和校验使用当前配置，不依赖栏目名称。起刊日期所在周为隔周第一周，起刊日前不排期。轮动仅使用有新评分的事件快照和截止前来源；无充分材料可省略，程序验证对应来源、字数和排期。默认一周观察至少引用三个不同事件。图表暂无独立生成器，采用材料支持的纯文字观点摘编。

## 发布与邮件

默认自动发布，关闭时保存待审稿。生成开始时读取发布模式，后续切换不追溯发布旧草稿。原正式快照在重生成期间保持可读。

首次正式发布、期号分配与投递落库使用事务，刊期并发操作用事务锁串行化。审核发布同时控制网页和邮件；出刊记录由待发布更新为已刊登。修订不重发，补刊始终待审且禁用自动投递。新自动投递只支持日报。

SMTP不保证端到端恰好一次。连接、认证或明确拒收保留失败原因；提交结果不确定时不自动重发。邮件使用同一份正式内容，保留原有墨蓝暖纸风格、表格布局和内联样式。半星在邮件中有数值回退。

## 管理与运维

- `/admin/editorial`：跳转栏目与篇幅；编辑规则分为栏目与篇幅、评分规则、收录与写作。
- `/admin/sources`：按RSS、公开接口、网页分组，显示近30天采入、关联淘汰及跨源重复事件数量。这是观察指标，不自动据样本不足淘汰来源。
- `/admin/articles`：统一任务与原始材料，出刊任务详情显示各栏目候选、五维评分和采用理由；资讯详情保留原始材料、阶段与模型回执，支持批次重处理。
- `/admin/settings`：任务并发、模型复核、采集、调用额度、自动发布和每日出刊。

模型接口、密钥、邮箱认证等运行连接在环境变量中；业务配置在数据库。单管理员会话以随机令牌哈希保存，写操作和详情接口都检查认证。

每源支持固定/自动采集间隔及上下限；同站预约限流共享，429遵守Retry-After。模型调用有每日次数保护、成功缓存、失败重试与预算等待；Worker每分钟检查当前刊期，不自动补齐长期缺刊。

迁移`0013_ai_daily.sql`新增assessment、标签和出刊记录，统一信源兼容键，关闭周月报并应用每日08:00和3.5分门槛。迁移前停止Worker。RSS核查与增配脚本见[README](../README.md)，历史信源检查见[sources.md](sources.md)。

## 阅读与历史

新日报快照格式为`ai-daily-v1`，直接按全局栏目展示，包含要览、半星和轮动。旧格式仍由原版式读取，保留原来源、日期精度和事实边界。

首页和归档仅提供日报。周月报原刊期链接继续可读；`/news`跳转日报首页，SSE及资讯查询能力留待后续恢复。所有阅读请求只读，不触发生成或模型调用。

## 批次重新处理

迁移0014新增reprocessing_batches与reprocessing_items，0015为栏目记录增加候选与评分明细。管理台操作只创建持久批次，Worker的tick及调度循环安排正常process任务；批次ID参与处理版本键，使显式重跑不会复用旧的完成阶段。预算不足保持等待，不重置尚未安排的资讯；已有活跃处理任务完成后再重跑，重复提交与并发调度受锁保护。

批次保存处理前的原始资讯状态。重处理完成后分类、评分、归组结果更新；无新事实但评分发生变化时只刷新该材料的编辑快照，不伪造新进展。未评分的旧事件不参与新流程的候选召回，避免旧事件将首条新评分吞成重复报道。旧关联失效的进展不再参与本期取材，历史正式快照仍不变。

可选的后续日报更新由正常generate队列完成，先生成待审稿，按当前自动发布开关决定是否发布，并显式禁止本次邮件投递。关闭自动发布时仍保留待审稿。独立出刊记录入口已移除，旧地址跳转任务管理。

日报成稿先校验事件引用与结构，再检测各栏目的标题和摘要合计字数。超预算时调用一次定向压缩，仅允许改写超限栏目的既有事件，校验事件集合、去重和字数，不允许添加或丢失事件；其他栏目、要览与来源保持不变。初稿与压缩结果分别缓存，重试复用已成功阶段。批次关联的失败出刊从任务管理重试时，关联到新的generate任务，仍保留禁止投递标记。

### 信源候选与栏目范围

`sources.origin_address`保存来源主页或账号，`url`保存可空的实际采集入口；`manual`表示待接入。`sections`为空数组时为通用，否则限定处理与出刊候选栏目。处理版本为`ai-editorial-v4`，范围进入处理缓存指纹；同一条资讯不会因多选栏目重复调用模型。

信源管理平铺列表，启停独立保存。新增默认关闭，`verification_status`区分待验证、技术可用、已选用、验证失败和暂不选用。验证只读外部列表与RSS，在来源记录保存样本与原因，不导入资讯、不调用模型、不启用来源。更换采集入口会撤销验证并关闭；已发布日报快照不受后续配置影响。

## 管理端职责

出刊管理保留刊期检查、生成、审核与重新生成，补刊位于其独立子页面。信源下分信源管理和信源监控；手工导入入口与自动采集总开关位于信源管理；任务管理负责执行状态、重试与批次重处理。编辑规则拆为栏目与篇幅、评分规则、收录与写作三个独立页面，保留表格原地编辑；订阅和推送记录通过页内导航分开，顶部提供添加订阅、手动推送和推送总开关。

系统设置为单页，保留模型额度、连接状态与数据保留；出刊设置位于出刊管理顶部弹窗，重试和并发配置位于任务管理顶部弹窗。疑难事实复核属于收录规则；主标题长度与整期事件上限属于篇幅规则。各页只提交本页字段，保存时锁定settings行后合并和校验，防止修改某页清空其他页配置。栏目改名仍通过原有事务同步信源关联。

标签配置和新分析标签生成已移除，旧字段只用于兼容历史数据；关键词仅匹配已采集材料并提供AI参考，不负责外部检索。editorialPrompt同时约束处理与成稿；结构、引用、分数门槛及篇幅仍有独立程序校验。

管理首页`/admin`展示真实运行数据，原刊期工作台迁至`/admin/publications`。今日入库按北京时间created_at统计；健康统计仅含启用信源，三次连续失败且最新仍失败才算连续失败；首采、重试、调度逾期分别显示，暂停自动采集不判定逾期。首页栏目表沿用最近一期edition_runs，不把正常留空或未排期标成异常。栏目description在分析与成稿提示词中起语义约束作用，不等同于程序硬校验。

推送总开关持久保存在settings.deliveryEnabled；关闭后不为新刊创建自动投递，拒绝手动推送，并在调度与实际发送时检查开关。已排队邮件保持待发送，重新开启后继续；已经进入发送过程的邮件可能完成。SMTP环境开关和配置仍须有效。信源监控按近30天现存采集记录、资讯记录及已发布日报引用统计，不将跨源共同报道当作无增量重复。

栏目支持拖拽排序，辅助关键词保存于各栏目。旧分组关键词在读取配置时迁入对应栏目；空白的已知固定栏目定位补齐默认要求，保留自定义内容。内部动态首次补充为关闭状态，后续仍可修改或删除。新生成日报保存sectionOrder，网页、目录和邮件均按快照顺序排列。历史快照不随当前顺序变化。
首页今日入库失败数按今日created_at统计；全部积压的失败数按全部state=failed统计。采集失败项按启用信源最新last_error统计信源数，避免将历史失败尝试持续累加。

批量重处理在任务列表中以reprocess类型呈现，一个批次一行，进行中的批次优先显示。子资讯和批次出刊任务收在批次详情，避免重复占用主列表；详情接口按需读取逐条结果。管理端失败项重试只将该批次失败资讯恢复为waiting，保留processed/ignored结果，由原调度器继续；仅生成失败时只重排该批次的出刊任务，并保留publishWithoutMail。批次查询、标签与重试逻辑位于仅管理端导入的模块，不改动Worker依赖的批次调度文件。
